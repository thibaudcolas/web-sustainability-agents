# Current WSG auditability

This inventory classifies **all 197 success criteria across 71 current WSG guidelines** by the evidence and judgment needed to assess them. It uses the [published WSG draft](https://www.w3.org/TR/web-sustainability-guidelines/), with the [16 October 2026 publication](https://www.w3.org/TR/2026/DNOTE-web-sustainability-guidelines-20261016/) pinned in the guideline-review skill. These are project assessment classes, not W3C classifications, conformance results or a count of implemented checks.

The five classes build on [Thibaud Colas’s assessment of WSG audit types](https://thib.me/assessing-web-sustainability-guidelines-on-automated-testing). Each decision below applies to the current criterion wording. Current criterion IDs and links are the index; guideline summaries collect their constituent classes.

## What the classes mean

| Primary class       | Criteria | What is needed                                                                                                                                                      |
| ------------------- | -------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Static analysis     |        3 | Inspect code, declarations or configuration using structural rules; no interactive journey is needed. Publicly delivered code can be sufficient.                    |
| Automated           |        6 | Run a repeatable runtime or HTTP procedure with explicit observable assertions and a declared scope.                                                                |
| Manual quantitative |       48 | Define a task, comparison or threshold, then interpret measurements. Scripts and agents can execute the procedure.                                                  |
| Manual qualitative  |       50 | Interpret meaning, relevance, usability, architecture or adequacy using public-facing behavior or supplied material.                                                |
| Consulting          |       90 | Assess organizational decisions, governance, resourcing, specialist context or sustained practice. Published records may suffice; otherwise request owner evidence. |

**Primary class** means the evidence needed to judge the complete current criterion within the stated audit scope. It is not the easiest detectable failure. A required title can be detected automatically, for example, while deciding whether optional head elements improve usability needs interpretation. **Supporting methods** identify useful partial checks; they do not make the entire criterion automatic.

“Manual” and “consulting” describe the kind of assessment, not who must perform it. An agent can conduct measured tasks, review qualitative evidence and inspect project records. It must retain uncertainty where evidence is missing. A public policy can support a policy-disclosure criterion; it does not establish that an operational process happens. Conversely, a criterion asking only for a published commitment should not be expanded into an audit of its execution.

Evidence access is separate from audit method. Database query comparisons can be quantitative even when they require backend traces; source review can be qualitative; a bot opt-out test can be automated even when the bot is not publicly runnable. Consulting is used where organizational context or sustained practice is integral, not simply because a file is private.

A guideline can contain several classes. Its summary below counts each criterion once by its primary class. Supporting methods do not enter those counts. The [implemented check reference](../reference/checks.md) separately records what this audit system can currently collect and judge; classification is not implementation or complete guideline coverage.

## Using the inventory

1. Select current criteria for the site, user tasks and audience. Read the linked WSG wording and supporting context before narrowing an expectation.
2. Choose representative pages, states and records. Collect repeatable facts with deterministic tools, then use the stated quantitative or qualitative review route.
3. Give reviewers the criterion, declared scope and evidence references. Separate observation, interpretation and missing evidence; do not treat agreement among models as new evidence.
4. Report tested scope and unresolved questions. Request the smallest useful additional record, task or comparison instead of converting inaccessible evidence into a failure or a pass.

This follows [STAR’s evaluation process](https://w3c.github.io/sustainableweb-ig/docs/star.html): define scope, explore, sample, evaluate and report. Public-site auditing is the default; optional source and organizational records extend what can be substantiated.

## Agent reference and maintenance

The `sustainability-guideline-review` skill packages criterion text in `references/wsg.json` and these classifications in `references/assessment-crosswalk.json`. The [published skill catalog](../agent-skills.md) exposes both. Load the relevant guideline group, not the whole inventory into every worker. The classification reference records the WSG version and content digest; full WSG attribution and licensing remain with the text reference.

Validate the current inventory against its pinned WSG reference:

```sh
uv run --locked --script audit/wsg_reference.py
```

A WSG update requires reviewing the affected wording and classifications together. No historic assessment download is needed to validate this inventory. This is planning metadata: an audit outcome still requires a scoped test or review and its evidence.
